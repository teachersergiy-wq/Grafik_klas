Grafik_klas — графік чергування учнів 7 класу
Ці інструкції призначені для ШІ-помічника, який змінює проєкт. Перед будь-якими змінами прочитай їх повністю.

Що це
Мобільний веб-застосунок: показує, хто сьогодні черговий у класі, і веде облік чергувань. Без сервера й бази даних: сторінка index.html на GitHub Pages, дані — у файлі data.json у цьому ж репозиторії.

Файли
* index.html — увесь застосунок (HTML, CSS і JavaScript в одному файлі, без збирання й залежностей).
* data.json — дані: список учнів і журнал днів.
* AGENTS.md — цей файл.

Налаштування в index.html (рядок CFG)
* owner: teachersergiy-wq
* repo: Grafik_klas
* file: data.json
* teacher: teachersergiy-wq (класний керівник)
* head: логін старости на GitHub (уточнити в користувача)

Формат data.json
```json
{
  "students": [{"id": "1", "name": "Прізвище І.", "b": 224, "ch": 35}],
  "days": {"2026-11-03": {"absent": ["2"], "duty": "5"}}
}
```
* b — дні в школі до початку ведення в застосунку (разом із днями чергування), ch — скільки разів чергував до того.
* days[дата].absent — id відсутніх учнів, days[дата].duty — id чергового.
* Дати у форматі РРРР-ММ-ДД. id — рядки, унікальні й незмінні.

Правила роботи застосунку (не ламати)
1. Зранку черговий не показується, поки не збережено присутність за день.
2. Черговий — той із присутніх, у кого найменший відсоток ch / b. За однакового відсотка: менше ch, далі за алфавітом.
3. Староста вносить дані лише пн–пт з 8:00 до 10:40 за київським часом, один раз за день, і не може змінювати вже внесене.
4. Класний керівник вносить у будь-який час і на будь-яку дату, може замінити чергового або скасувати запис.
5. Учні лише переглядають, без входу.
6. Вхід — через токен GitHub (fine-grained, лише цей репозиторій, право Contents: Read and write). Роль визначається за логіном власника токена.

Вимоги до змін
* Інтерфейс українською, орієнтований на телефон: великі кнопки (від 48 px), одна колонка, шрифт не менше 16 px.
* Не додавати збирання, фреймворки та зовнішні бібліотеки без прямого прохання.
* Не зберігати в репозиторії токени, паролі й повні прізвища дітей (лише «Прізвище І.»).
* Після змін перевіряти, що сторінка відкривається, і не змінювати формат data.json без міграції наявних даних.
* Пояснювати зміни простою мовою, без технічного жаргону: користувач — вчитель, не програміст.
